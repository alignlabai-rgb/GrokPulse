#03 1C2V / 仮置き
技術報告・試算
余った VECTOR は、貸さなかった
32 は、試算コードの変数だ
FlashMLA の docs/20260930-ascend-prefill-deep-dive.md を、本稿は開いた。252 行。導入は、9 月 30 日に昇騰の疎な prefill と decode を開いた、と書き、V4.1 の典型負荷で prefill 410、decode 360、つまり理論ピークの 95% と 83%、と README と同じ数字を一人称の報告が引き受ける。典型、の分布は、その段落に無い。無い分布を、本番の平均にするな。アーキテクチャとして事実形で書いてあるのは、昇騰 950 の各 AI Core が CUBE 一つと VECTOR 二つを持つ、ということだ。著者は 1C1V を検討し、余った VECTOR で模型の別モジュールやデバイス間通信を回して MFU を上げる、という道を明示して、捨てた。捨てた理由は三つ。MTE2 の発行キューは、一つの VECTOR で同時に未完了 16 本まで。gather2 でも飛行中のトークンは 32 で、足りない。decode の逆量子化は、1C1V だと CUBE に追いつけない。FixPipe は 1C1V だとサイクルあたり 128 バイトで、タイルを大きくしないと計算より遅くなる。大きくすると、キューがまた足りなくなる。結論は 1C2V。通信に貸す予定だった片側を、注意の核が自分で食べた。食べたことを、チップに通信エンジンが無い、と拡大するな。拡大してよいのは、この核の設計が、余白の VECTOR を残さなかった、ということまでだ。32 は、別の強度だ。ヘッド数を決める試算コードが num_cores = 32、freq = 1650e6、l2_total_bw = 5e12 と置き、CUBE がフルスループットならサイクルあたり AI Core ごとに 4096 FMA、と仮定する。仮定の隣に、L2 を 5 TB/s と置く同じブロックがある。ブロックの中の数を、一部は仕様、一部は例え、と著者がラベル分けしていない。分けていない仮置きを、華為の公示表にするな。本稿が、FMA を 2 flop として 4096 × 2 × 1.65 GHz × 32 を掛けると、BF16 で約 432.54 TFLOPS になる。DeepGEMM の表の分母は 432 だ。FP8 をその 2 倍、FP4 を 4 倍にすると 865 と 1730 に、整数で合う。合致は、分母の出どころがこの試算と同じ族だ、という本稿の検算であって、上限を第三者の機械で測った記録ではない。Zhihu Frontier が金曜 14:03 GMT に置いた要約は、歪睿老哥の読みとして、32 AI Core、CUBE 32、VECTOR 64、BF16 約 432、FP8 約 865、FP4 約 1730、CUBE 一つあたり FP8 約 27 TFLOPS、と推定している。865 を 32 で割ると約 27.0 だ。推定は、技術報告の仮置きを外へ読み上げた形に近い。本稿は、歪睿老哥の元投稿を開いていない。開いていない元投稿を、華為の白皮書にするな。より強い記述として同じ報告が書くのは、命令キャッシュが CUBE 32K、VECTOR 16K、SIMD VF 8K で、L1 が 0–256K と 256K–512K の二銀行に割れている、ということだ。これも、著者がチップの性質として書いている文であって、本稿がデータシートの版を突き合わせた結果ではない。突き合わせていない容量を、発注仕様にするな。ヘッドは 64 / AI Core を採り、128 は L0C が溢れるので捨てた、とも書く。64 を、あなたの模型のヘッド数の義務にするな。契約に「32 コアが華為の公示だ」「5 TB/s が HBM の仕様だ」「432 を第三者が測った」「1C2V がチップから通信を削除した」「27 TFLOPS がカタログの一コアだ」「金曜の X が新しい仕様を発表した」と書くな。「1 CUBE + 2 VECTOR は技術報告の事実形。1C1V は通信へ貸す案ごと捨てた。32、1.65 GHz、L2 5 TB/s、4096 FMA は試算の仮置きで、本稿の掛け算が BF16 約 432.5 になり表の分母と合う。95% と 83% は典型負荷という自測。歪睿老哥の元稿は未開」と書け。
