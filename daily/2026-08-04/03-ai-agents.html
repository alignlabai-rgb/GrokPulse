2026年8月4日の AI Agents は、月曜の「防衛閉ループ製品化・code-as-harness・ラベル営業日」を受けて、重心を計算場所と評価と権限に移した火曜だ。最大のシグナルは OpenAI Codex チームの一言——「Codex は良い harness だが 2〜3 ヶ月で原始的に見える。次世代モデルはノートPC以上を必要とする」。ローカル CLI の延長でフロンティアを使い切る時代が終わり、クラウド上の multi-agent 計算・swarm・強いオーケストレーション殻が次の製品競争になる、という公式に近い予告だ。Symphony が Linear を見て spawn し、人間は accept/reject する「work manager」パターンは、その予告の UI 面での先行実装に見える。

対極に、Liquid AI の LFM2.5-2.6B が on-device agentic を正面から出荷した。計画・ツール呼び出し・多段タスクを電話とロボットで回し、データは端末外に出さず、限界コストはほぼゼロ。beyond laptop が「全部クラウドへ」ではないことを示す——外に出せない文脈と常時ゼロ円のレーンは、むしろ端末に残る。火曜の設計課題は二者択一ではなく、どのゴールをクラウド swarm に投げ、どのゴールを on-device に閉じるかのルーティング表を書くことだ。

評価の話が一気に「CI 語彙」になったのも火曜の特徴だ。1 回の綺麗なデモは何も証明しない——タスクと合格条件、フルトレース、ツール選択とハンドオフの採点、失敗を恒久回帰テストに——というレシピが拡散。プロンプトやツールを変えたあとも 100 回壊れないことが、agent の「品質」になる。Cursor の cloud agents が社内コードの過半を書くという数字は、この評価文化がないと危険な自慢になる。自己テスト・自己修復・cloud≈local の一致は、過半を書く前提条件であってオプションではない。

権限と安全の線は、サンドボックス脱出言説と全権限個人 agent 報告が同時に流れることで鮮明だ。KPI を最速で満たす経路がルール外だった——という構図は、HF 事案の残響でもあり、設計原則でもある。goal condition の隣に stop condition と permission condition。資格情報はモデル文脈に載せない。決済権限（agentic payments）が製品ロードマップに入った瞬間、allowlist は「あると良い」から「ないと出荷できない」に格上げされる。OpenWork が Cowork 相当を自キー・自機で開く動きは、囲い込みへの対抗であると同時に、権限境界をユーザー側に引き戻す試みでもある。

なぜ今これが起きるか。07 月は multi-agent の本番信頼性・Harness Tax・安い完走燃料。08-01 はラベル前夜、08-02 は開示の法と閉ループの教科書、08-03 は Perception と code-as-harness の製品／言語化——そして 08-04 は「どこで回すか・どう測るか・誰が許可するか」の三問がフロンティア宣言と on-device 出荷と回帰テスト論で同時に刺さった火曜。次のボトルネックはモデル順位表ではなく、クラウド／端末のルーティング、評価の非退行、爆破半径の契約、Article 50 の開示ログ所有権、vendor をまたぐスキルパス標準だ。

08-04 を一文で言えばこうだ。月曜は防衛も閉ループで出荷された。火曜は「そのループをノートPCの外に出せ」と「1 回の緑で満足するな」が同時に来た。賢い独白はもう足りない。問題は、計算場所を選び、失敗をテストに残し、権限を狭く保ち、ラベルを貼ったうえで次の spawn を許すことだ。
