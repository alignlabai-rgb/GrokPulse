GrokDigest

2026年8月3日の AI Agents は、日曜の「ラベル Day Zero・plan/build/judge 教科書化」を、平日の製品出荷と Runbook に変換する月曜だ。最大のカレンダーイベントは Microsoft Project Perception 公開プレビュー——Defender 内で Red／Blue／Green の専門 agent が攻撃経路探索・リスク判定・修正作動を連続ループする。Security Copilot が対話で支援する世界から、「agent が動いて人間が臨界判断を握る」世界への製品シフト。社内 coding agent への写像は直截：観測・判断・作動を同一プロセスに独占させるな、という Sunday の教訓が、今日 SOC 製品の仕様書になった。

同じタイムラインで、設計語彙は code-as-harness に寄った。非制約の LLM ループはタスクがスケールすると state drift と無効 API 呼び出しを生む——だから Context Scaffolding、VM 隔離サブ agent、Zero-Sleep ツール実行、コンパイラ／リンタの Evidence Gate、グラフ fan-out、チェックポイント merge という六層を「プロンプト」ではなく実行可能な基板にせよ、という月曜の拡散。YC が開源した QM は、その企業版の実物：durable state、vendor-neutral エンジン、Slack と cron とサンドボックス。メッセージは一貫している——agent を増やす前に状態層と権限契約を建てろ。

実装側は並列化とコスト計器で忙しい。並列 coding agent が better／faster／cheaper をプログラム可能な選択にする、マルチモデルスタックは「好きなモデルの棚」ではなく orchestrator・境界付き worker・独立検証・証拠ゲートの OS だ、という論が月曜 RFP に落ちる。mcp-use v2 は 7/28 の stateless MCP 仕様に追いつき、手足層のバージョン契約を更新。無料フロンティア経路（Qwen in Claude Code 等）と出力トークン削減ハックは、「枠が溶ける」が艦隊の真のボトルネックになった証拠——ただし請求スイッチの罠と監査ログ欠落は別の障害モードだ。

制度面では Article 50 の最初のフル営業日。対話系・agents・coding agents の開示、合成物マーク——法務と CI が同じゲートを持つ。Perception が agent で防衛する一方、Agent 365 系の runtime 保護は「deploy された agent そのもの」を守る二正面。燃料が安いほど爆破半径を狭くしろ、サブ agent に必要なのはループではなく権限の契約、という原則は HF 事案以降の保険ではなく設計要件として定着する。

なぜ今これが起きるか。07-07 以降 multi-agent は本番信頼性へ、07-18〜24 は工場規格と請求書、07-25〜30 は Harness Tax と Workspace、07-31 は安い完走燃料と可搬性、08-01 はラベル前夜と attention 選定、08-02 は開示の法と閉ループの教科書——そして 08-03 は防衛閉ループの製品化・code-as-harness の設計言語化・ラベル営業日・並列艦隊の OS 化。次のボトルネックはフロンティアの順位表ではなく、役割分離の実装、検証ゲート、状態層の耐久性、vendor failover、週次枠の可視化、agent 数に比例する監査コストだ。

08-03 を一文で言えばこうだ。日曜はプレートが義務になり、運転は plan/build/judge の周回コースになった。月曜は同じ型が Defender の Red／Blue／Green として出荷され、coding 側はプロンプトを捨てて検証基板を組み、営業日の CI がラベル漏れを落とす。賢い独白はもう足りない。問題は、閉ループで守り、殻で完走し、権限を狭く保ち、燃料計を見ながら次の spawn を許すことだ。
